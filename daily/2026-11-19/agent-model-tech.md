## 今天先看

**模型竞争继续转向单位任务成本；Agent 的另一条关键瓶颈，是多方证据在记忆和委派过程中被过早压缩。** 前者看缓存与输出效率，后者不能只看检索是否命中，还要看冲突证据能否完整到达最终决策环节。这是本期综合判断，不是单篇研究已经证明的产业结论。

## 1. GPT-6.2 Astra / Sol：关注任务成本，而不只是单价

**时间与状态：** 11 月 17 日官方发布，属于近 7 日补充；API 提供，Work / Codex 的发布说明标为预览。

Astra 面向复杂专业任务，Sol 偏向高频、效率敏感场景。官方重点包括减少输出 token、缓存复用与多轮推理效率，没有公开足以支持架构层推断的细节。

标准 API 每百万 token：Astra 输入 / 缓存输入 / 输出为 **8 / 0.40 / 40 美元**；Sol 为 **2 / 0.10 / 10 美元**。厂商建议保持提示词前缀稳定，把新增指令追加在后，以提高缓存复用。

**为什么值得看：** 单任务成本同时受调用次数、输入长度、缓存命中、输出长度影响，不能把降价比例直接换算成业务成本下降。对长流程 Agent，选型应比较同一任务完成条件下的总耗费，而非单轮回答的 token 单价。

**边界：** 性能与效率改善来自官方报告，本期未复现；价格为发布材料所列标准口径，不代表所有服务层级。

来源：[官方发布](https://openai.com/index/introducing-gpt-6-2-astra-sol/) · [产品发布说明](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

## 2. AssemblyAI STT 3.7：把实时转写与 Agent 轮次判断拆开

**时间与状态：** 官方正文标注 11 月 18 日，部分搜索索引仍显示 17 日，以正文为准，不推断精确上线时刻。

新系列分为普通实时、实时 Agent 与录音转写三种模型。普通实时侧重会议、字幕和说话人标注，**不承担对话轮次判断**；Agent 版本侧重识别面向助手的发言、压制背景语音，并处理简短回答与数字。

官方报告 Agent 版本在语音结束后约 **86 ms** 产出最终转写。这个数字不是完整语音助手的端到端响应延迟，不能忽略后续模型推理与语音合成。

**为什么值得看：** “能实时转写”与“知道用户说完了、正在对助手说话”是不同能力。语音 Agent 的入口选型开始按交互形态细分，而不是只比较识别准确率。

**边界：** 延迟与效果为厂商披露，未独立复现。

来源：[官方发布与模型差异](https://www.assemblyai.com/blog/introducing-assemblyai-stt-3-7)

## 3. 多 Agent 为什么读到了冲突，却没有报告冲突？

**时间与状态：** 11 月 17 日提交的研究预印本，近 7 日研究补充，非生产系统普遍结论。

《Where Factual Conflicts Disappear in LLM Agents》在 11 个尽调任务中植入 73 处数字冲突，跟踪“源文档读取 → 子 Agent 报告 → 主 Agent 证据 → 最终报告”的链路。

在其设定下，强制委派组读到冲突双方的比例更高，但最终冲突检出率反而低于单 Agent；**可选委派组表现更好**。因此结论不是“多 Agent 一定更差”，而是分工与摘要接口可能让本已检索到的证据消失。

**技术启示：** 子 Agent 返回的内容应保留相互矛盾的主张及其来源，不应只交付已经“调和”的结论。协调者能否看到共同证据，与增加多少 worker 同样重要。

**边界：** 强制委派同时改变了来源分区和主 Agent 的文档访问权限，不能把结果单独归因于 Agent 数量；样本集中于植入数字矛盾的尽调文档。

来源：[论文摘要](https://arxiv.org/abs/2611.22245) · [正文](https://arxiv.org/html/2611.22245v1)

## 4. DebateGraph：记忆系统不应急着替 Agent 消除分歧

**时间与状态：** 11 月 17 日提交的预印本，属于研究验证，尚不能视为成熟通用方案。

这项消融研究比较多种记忆后端与机制：保留带来源的冲突集合，还是按新旧、信任度等规则提前收敛成一个答案。研究支持让下游推理阶段看到分歧，而非在记忆层静默抹掉它。

一个尤其值得注意的细节是：初始检索上限隐藏了约 75% 的注入矛盾，扩大上限后效果差异才充分显现。**存储了证据，不等于检索时把证据交给了模型。**

**技术启示：** 记忆结构不仅需要“当前值”，还需要主张、来源、有效期与冲突关系。检索预算会改变系统实际上可见的事实集合。

**边界：** 实验主要使用同一模型；部分任务上的全上下文基线优于检索方案。论文不支持“图记忆普遍优于全上下文”，也不构成对所有提示注入攻击的防护保证。

来源：[论文摘要](https://arxiv.org/abs/2611.22461) · [正文](https://arxiv.org/html/2611.22461v1)

## 本期判断

- **短期关注成本口径：** 看完成一次任务的总成本，不只看价格表或单轮 token 数。
- **中期关注证据接口：** 将“冲突保留、来源可追溯、协调者可见”视为 Agent 记忆与委派协议的一部分。
- 两篇论文指向相邻问题，但研究任务和条件不同，不能把结果拼成已经完成的端到端方案。

本期没有采用未经核实的热度排行，也没有把上述研究包装为已落地能力。
