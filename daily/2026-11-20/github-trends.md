## 一、全站热点：基础设施与协作工具

### 1. NGINX：网关测试的基础参照，不是 Token 调度器

**热度：总 Star 32,342；今日 +73。** 本次周榜未见。

- **解决什么、适合谁：** 官方开源 Web 服务器、反向代理、负载均衡和缓存，适合网关及平台工程团队。对推理平台，值得复用的是连接、超时、限流、上游故障等测试视角。[项目](https://github.com/nginx/nginx)
- **近期证据：** 11 月 18 日有 `Version bump` 提交；11 月 11 日提交标记为 `nginx-1.31.9-RELEASE`。版本变更不是今天上榜原因的证据。[提交](https://github.com/nginx/nginx/commit/2e8440bcdc438f0f1cd03da778a3843ddb3c86d9)
- **边界：** 通用 HTTP 层能力不等于面向 Prefill/Decode、KV Cache 或 Token 预算的调度。做 LLM 网关仍需单独验证流式中断、慢消费者和上游排队。

### 2. AFFiNE：文档、白板与结构化知识工作区

**热度：总 Star 75,185；今日 +182。** 本次周榜未见。

- **解决什么、适合谁：** 把文档、无边界画布和结构化数据放进同一工作区，支持本地优先及自托管，适合团队知识管理、设计和协作整理。[项目](https://github.com/toeverything/AFFiNE)
- **近期证据：** 11 月 17 日修正文档引用的标题解析，关注点是关联文档标题变化后的显示一致性。[提交](https://github.com/toeverything/AFFiNE/commit/dc2b2212441602452f3cf0ea50a4eaedaf03bcc2)
- **边界：** 本地优先不等于所有 AI 能力离线运行。若用于内部质量知识库，应先核实 AI 请求去向、同步权限和部署版本；不要把社区版许可直接套到所有商业功能。

## 二、AI 专项：开发验证、训练学习与可靠性

### 3. Superpowers：把“写完了”变成可检查的开发流程

**热度：总 Star 322,105；今日 +2,028。** 本次周榜未见。

- **解决什么、适合谁：** 面向编程 Agent 的技能与工作方法，串联需求澄清、计划、TDD、子任务执行、评审及完成前验证。适合已有 AI Coding 实践、想减少返工的研发与 QA 团队。[项目](https://github.com/obra/superpowers)
- **近期证据：** 当前最近返回的提交是 11 月 3 日 `v7.0.2`，涉及 brainstorming、运行宿主启动及 SDD 辅助工具修复；不是今天发布。[提交](https://github.com/obra/superpowers/commit/22f0b463e7a5e579904dd6211a520321035526f7)
- **边界：** 有验证技能，不代表自动获得可靠测试结论；模型、工具权限及仓库测试质量仍影响结果。MIT 开源，不代表所接模型服务免费。

### 4. MiniMind：适合训练链路质量演练的小模型项目

**热度：总 Star 66,896；今日 +238。** 本次周榜未见。

- **解决什么、适合谁：** 提供小模型预训练、SFT、LoRA、偏好优化及强化学习等代码，适合希望理解训练流程、构建轻量验证环境的工程师。[项目](https://github.com/jingyaogong/minimind)
- **近期证据：** 11 月 18 日有解码调整，以及“先累计 LoRA 增量，再舍入合并权重”的修复提交。后者值得转化为权重合并数值精度的回归案例。[提交](https://github.com/jingyaogong/minimind/commit/9f05da1c3d3b4e5dc9257a525bf19e99acee401b)
- **边界：** README 的“两小时／约 3 元”有特定 SFT 单轮、单卡 3090 和当时租价口径，不能理解为任意完整训练任务的保证。教学模型也不是生产模型效果或性能基准。

### 5. OpenSRE：从失败 CI 到证据驱动的排障

**热度：总 Star 13,141；今日 +38。** 本次周榜未见。

- **解决什么、适合谁：** 面向 CI/CD 可靠性，关联失败检查、日志、提交及其他运行信号，并提供分析和修复工作流。适合平台测试、DevOps 和 SRE 团队做排障辅助研究。[项目](https://github.com/Tracer-Cloud/opensre)
- **近期证据：** 11 月 18 日修正环境配置、Secret 默认值与工作区身份来源，涉及 linked worktrees，说明工具运行上下文本身也是质量关注点。[提交](https://github.com/Tracer-Cloud/opensre/commit/29d9ba64ffe3d19abf1e02d0b8f711106a565a87)
- **边界：** 官方明确为 Public Alpha，接口和集成仍在变化；具有写入修复分支等能力，不宜直接给予生产自动修复权限。建议仅用脱敏历史 CI 失败做只读评估。

- **近期证据：** 11 月 18 日合并 README 补充 `site-md` 技能的文档变更。这是文档更新，不能当作当天新能力发布。[提交](https://github.com/google-labs-code/stitch-skills/commit/4cf4db8e4143b09e40f9bc887429d81f41ab3947)

## 趋势判断

以下是基于本期样本的判断，不是全行业统计：

1. **Agent 的竞争点开始包含工作过程。** Superpowers 将规划、测试、评审和验证串起来；值得衡量的是是否减少返工，而不只是生成速度。
2. **AI 工具自己的工程缺陷同样值得测试。** MiniMind 的权重合并精度、OpenSRE 的工作区身份和配置来源，都是能落到回归用例的具体问题。
3. **技能标准化不等于跨工具即插即用。** Stitch Skills 展示设计工作流复用方向，但运行宿主、权限、外部服务和能力映射仍需分别验证。

## 今天建议只做两件小事

- **先试 Superpowers 的验证流程，不急着全量接入。** 用同一组历史缺陷，对比现有流程与“先写失败测试、再修复、最后跑完整相关回归”。记录有效缺陷检出率、误报、人工复核时间与返工次数。
- **把 MiniMind 的 LoRA 合并修复做成精度回归题。** 固定权重、数据、随机种子与精度配置，比较合并前后权重误差及输出差异，阈值由基线实测确定；不要简单要求每个生成 Token 完全一致。

Star 只作发现线索，不作成熟度或采购结论。以上均为调研建议，未执行安装、授权或生产接入。
