# 大模型与 Agent 质量、测试与工程资讯｜2026-11-24

**观察窗口：北京时间 11 月 23 日 09:30 至 24 日 09:30。** 6 个主题、7 项已合入变更。**本期优先补两道门禁：健康探针通过后再验首条真实请求；工具调用完整与整轮完成分开断言。** 下列实测为上游报告，另标公开 CI；未独立运行。合入不代表已发稳定版。

1. **就绪、首个可见文本与真实首请求，是三件事。** [vLLM #69076](https://github.com/vllm-project/vllm/pull/69076)，24 日 02:15 合入：从启动进程前分别计时到 /health 首次 200、固定 greedy 流式请求的首个非空文本。后者包含就绪后的模型列表查询，不是首个 SSE 事件。双 B300、Qwen3-32B TP2，作者测得 1 次冷启动 109.97 秒、3 次暖重启中位 67.77 秒；“冷”清了 vLLM、Inductor、Triton 缓存，权重已在本地且页缓存热。后续输出与首轮文本和 token ID 一致，只证明该条件下重复一致。[Dynamo #19339](https://github.com/ai-dynamo/dynamo/pull/19339)，24 日 02:11 合入：作者估算历史 Blackwell CI 中约 8% 的该用例首个图像缓存填充请求 60 秒未出 token，尽管已取图并调度，同会话重试很快。A100 强制 PTX 实验只支持首次 JIT 假设，未复现 HTTP 超时，Blackwell 根因未证实。补丁只把该测试请求预算 60→180 秒、整案 400→720 秒；两个 CI 作业（[400 秒版](https://github.com/ai-dynamo/dynamo/actions/runs/44970135843/job/137050851537)、[720 秒版](https://github.com/ai-dynamo/dynamo/actions/runs/44975718187/job/137067881383)）通过并不证明生产提速或超时消失。
2. **整轮被长度上限截断，已完成的工具调用不该一并丢失。** [Dynamo #19301](https://github.com/ai-dynamo/dynamo/pull/19301)，24 日 02:24 合入。作者从代码发现聚合器按参数能否解析为 JSON 保留调用，漏掉 Mistral 已确认完成的原生调用；部分流式 custom 路径类似。修复保留已确认调用与原参数、拒绝仅在收尾时闭合的调用，整轮仍是 length 或 incomplete。CPU 上经真实解析器和转换器验证，非流式 6 个场景各 3 种事件分块，另有 2 个流式回归；无 GPU 端到端证据。建议同序列核对两个接口的参数原文、调用完整性与终态。
3. **非对称 INT8 先舍入再减零点会损失有效精度。** [vLLM #69085](https://github.com/vllm-project/vllm/pull/69085)，24 日 03:49 合入。作者因 ROCm 换镜像后模型分数跌破门槛追到 BF16 舍入误差，改为 INT32 累加器先减零点。MI300X，ROCm 10.0/10.1 两种镜像，算子用例均从 4 失败、149 通过、1 跳过变为 153 通过、1 跳过；8B harness 严格匹配 0.708→0.740、0.696→0.732，阈值 0.703。建议先和精确整数参考及舍入容差对照，再看模型分数；不是广泛性能证据。
4. **“发压不足”也可能是准入窗口已满。** [Dynamo #19335](https://github.com/ai-dynamo/dynamo/pull/19335)，24 日 03:02 合入。旧判据把发压线程等待都算成压测器瓶颈，连 512 个准入名额占满也计入；改用等待结束时空闲占比加权，是上界近似。作者在单 Grace、同 AgentX 语料做 3 组配对：等待占比 10.3%–10.6%→2.9%–3.2%，有效轮次 0/3→3/3，实际预订速率近似不变；削弱发压器的单次负控仍被判无效。实测为较早提交，队列场景仍可能被工具控速；不等于生产 Router 提速。
5. **跨硬件 CI 要验证“真跑”，不只数登记。** [SGLang #51523](https://github.com/sgl-project/sglang/pull/51523)，23 日 17:47 合入。原有 73 个 CUDA 文件无 AMD PR 登记；作者排除 HIP 全跳过、无摘要、删除与基线失败项。基于历史 MI300/ROCm10 确认至少执行真实用例；当前主线加首批改动，68 个文件 67 通过，失败者未纳入；其余 6 个另有运行记录。AMD 基础检查显示成功，不能代替其他 tier。建议覆盖表同时列登记、执行、全跳过和排除原因。[运行记录](https://github.com/sgl-project/sglang/actions/runs/44504934853)
