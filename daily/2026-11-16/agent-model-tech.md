## 1. Edge0：把大参数模型的压缩与异构推理一起设计

**日期与状态：**官方介绍发表于 11 月 12 日，仓库发布记录标注 11 月 13 日；模型与运行工具已发布。两者日期不同，不将后续媒体转载日视为首发日。

Edge0 145B/120B 基于 Qwen3.8-Flash-Next，结合稀疏专家、专家输入降维及 CPU/GPU 间权重调度。145B 版本每次激活约 10.12B 参数，重点是降低大参数模型在本地运行的资源门槛，而非重新训练一款独立基础模型。

**价值：**值得关注的是模型结构与内存调度的联合优化，适用于研究本地 Agent、隐私敏感任务及有限显存部署。

**限制：**激活参数少不等于权重、内存和带宽需求小。官方不同量化格式并非分别完成了质量评测；“16 GiB 显存”配置中的部分结果来自限制资源后的 RTX 5090D，而非另一张原生 16 GiB 显卡，不能直接外推。官方速度与质量数字仍缺少本期核实的独立复现。

来源：[官方介绍](https://edge0.ai/blog/introducing-edge0-145b-frontier-ai-capabilities-on-your-own-computer) · [仓库](https://github.com/Edge0-AI/Edge0) · [模型与硬件测试说明](https://github.com/Edge0-AI/Edge0/blob/main/docs/models/edge0-145b.md)

## 2. Agweb：浏览器工具从“全量截图”转向增量观察和多 Agent 工作区

**日期与状态：**11 月 14 日公开社区展示；已有公开项目，不将展示日等同首次代码发布日。

Agweb 使用 macOS WebKit，为不同 Agent 提供工作区和标签页；动作返回页面变化，支持差量快照，减少重复读取完整页面的需求。它同时保留人类可见的操作界面，避免自动化窗口反复抢焦点。

**价值：**技术意义在于改进工具反馈与上下文组织，而不是提升底层模型能力。适合研究多 Agent 并行浏览及人机交接。

**限制与热度：**需要 macOS 26+，不支持 CDP，不能直接替代所有 Chromium/Playwright 流程。共享登录配置也会共享状态影响，工作区分离不等于安全隔离。观察时，其 Hacker News 讨论为 **107 分、37 条评论**，讨论涉及并发会话与兼容性；这只是社区关注快照，不是可靠性或持续增长证明。

来源：[项目 README](https://github.com/paul-nameless/agweb) · [作者介绍及社区讨论](https://news.ycombinator.com/item?id=50497147)

## 3. FlowPlan：用程序图组织规划，减少编码 Agent 的重复检查

**日期与状态：**论文首次提交为 11 月 9 日 UTC，即北京时间 11 月 10 日；研究预印本，提供复现包。

FlowPlan 让 Agent 先在函数级控制流图或数据流图上定位问题，把修改计划表达为明确的图变化，再检查实际修改是否符合计划。它试图减少反复读取源码、查看差异与延长对话轨迹的成本。

**价值：**在作者的 6 个“模型×基准”设置中，修复成功率未出现统计显著变化，5 个设置的 token 消耗显著下降。其启示是：上下文工程不仅要压缩输入，也要为工作流程提供明确的结束条件。

**限制：**每个实例只运行一次，覆盖同一供应商的两个模型与三个基准；图抽象会遗漏跨函数语义。图变化一致不是程序正确性的证明。总 token 降幅也不能直接当作费用降幅，缓存读写结构会影响实际成本。本项聚焦规划机制，不重复展开缺陷回归流程。

来源：[论文及完整实验限制](https://arxiv.org/html/2611.13241v1) · [复现包](https://github.com/MelikaSepidband/FlowPlan)

## 4. TreeAgent：让长上下文记忆保留 JSON、HTML 的层级关系

**日期与状态：**11 月 10 日提交；研究预印本，提供公开代码。

TreeAgent 不再只按固定 token 数切块，而是尽量保留完整子树与相邻兄弟节点，并为分块附加结构路径。它还将历史子节点记忆连接到父节点处理过程，减少连续压缩造成的字段关系丢失。

**价值：**适合长 API 响应、网页结构和配置数据的检索与聚合。作者在 4 类记忆 Agent、8 类任务和 8K 至 1M token 输入上评估，报告整体改善；方法不要求主实验重新训练模型。

**限制：**依赖可解析层级，不能外推为通用长文本记忆方案。JavaScript 实验针对静态对象数据，不是程序理解或执行。每个条件只评估一次；匹配分块数量也不等于计算量完全相等，部分配置增加了调用次数。安全与越狱鲁棒性未得到验证。

来源：[论文及实验范围](https://arxiv.org/html/2611.13946v1) · [项目代码](https://github.com/ZJU-LLM-Safety/TreeAgent)

## 值得继续关注的两个方向

1. **结构化上下文，而不只是更长上下文。** FlowPlan 和 TreeAgent 都利用任务已有结构减少信息重建负担。可优先阅读其输入表示和预算对照，而非只看最终分数。
2. **Agent 工具与运行环境的联合设计。** Agweb 优化观察与交接，Edge0 优化模型与硬件协同。落地时应分别核对任务成功率、状态隔离、实际延迟和完整资源成本，不能把省 token 或单机速度当作端到端收益。
