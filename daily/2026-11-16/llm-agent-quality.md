# 大模型与 Agent 质量保障简报｜2026-11-16

**观察窗口：北京时间11月15日09:30至11月16日09:30，结合近7日背景。** 本期精选6项窗口内合入的工程质量改进，均属于**测试AI系统**。其中部分问题早于本周发现，今天的新进展是修复合入，不是首次发现；合入主分支也不等于已经进入稳定发行版。下面的执行结果来自原作者或公开复核者，本次没有运行代码。

## 1. vLLM：前缀缓存“命中更多”，可能反而漏算上下文

**日期／状态：11月15日提出，北京时间11月16日06:59合入。**

- **发现证据：**Mamba `align`模式在块内恢复prefill，并跨过块尾时，仍可能把恢复点的旧状态登记为完整块状态。作者提供缓存开／关差分复现，未披露更早的发现过程，不能称为线上事故。
- **触发与复现：**单GB300、`ibm-granite/granite-4.0-tiny-preview`，开启前缀缓存，`prefix_match_unit=16`、密集保留、SSM缓存FP32、eager模式。块长为832；依次发送17、1681 token前缀，再发送858 token查询，最后清空缓存重跑查询。PR有完整脚本。
- **预期／实际：**正确答案是`pillow`。旧实现报告命中832 token，却用16 token处的状态，回答错误；修复后首次只命中16 token，输出与无缓存一致。
- **回归：**已增加`test_mid_block_resume_running_past_block_end_does_not_cache_it`，覆盖本地、共享分叉与外部恢复，检查错误块不以完整块键发布。作者报告旧实现失败、修复后通过，各重复3次。
- **限制：**首次有效命中长度下降是正确性代价，不是性能回归已被消除；该GPU复现不代表所有混合模型均已验证。

来源：[根因、完整脚本和测试](https://github.com/vllm-project/vllm/pull/67717)。

## 2. vLLM：长上下文的风险不是只有OOM，还有地址偏移溢出

**日期／状态：11月5日报告，北京时间11月15日23:27修复合入。**

- **原始发现：**8张MI355X、DeepSeek-V4.1-Flash-1017、TP8开启DSpark自适应验证时，启动约7分钟发生GPU内存访问错误。原始issue包含镜像、PyTorch／ROCm版本及启动命令；关闭自适应验证可启动。
- **定位方法：**串行kernel与详细日志将故障指向K-cache gather。请求stride本身未超限，但`batch_idx × stride`用int32计算，打包区域超过`2^31`元素时溢出。
- **复现／判定：**PR提供上述启动命令，以及`tests/kernels/test_compressor_kv_cache.py::test_v41_gather_rows_past_int32_elements`。新测试让各请求读取同一缓存块，要求最后一行与首行**零容差一致**；每项隔离到子进程，避免GPU故障拖垮测试集。
- **前后结果：**当前版本kernel测试从3失败、145通过、58跳过，变为148通过、58跳过。较早修复版本的服务验证为2/2启动成功；该服务结果与当前kernel测试不是同一修订版。
- **限制：**普通共享长前缀突发也可能触发越界，作者观察过未出现可见输出变化的情况，因此“回答正常”不能排除写坏内存。性能成本未测，不能泛化到所有后端。

来源：[原始报告](https://github.com/vllm-project/vllm/issues/65925) · [修复、阈值及测试入口](https://github.com/vllm-project/vllm/pull/65926)。

## 3. SGLang：取消接口返回200，不代表计算真的停止

**日期／状态：北京时间11月16日07:24合入。**

- **检出过程：**作者从双socket控制路径建模出乱序，再在引擎复现：请求走所属DP rank，取消消息却经rank 0广播，可能先于请求到达，调度器找不到请求便忽略取消。
- **触发条件：**基线`d800cb859e85`、2张GB200、Qwen3-0.6B，`--tp-size 2 --attn-dp-size 2`，默认控制路由。将流式目标固定在rank 1，rank 0积压128个短请求，提交后0–20毫秒取消。
- **前后结果：**旧版200次中19次丢失取消，继续生成完整512 token；修复后0/200丢失，均以`abort`结束。在更强制的轮询／积压条件下，从16/16丢失变为0/16。
- **回归：**CPU测试驱动真实分发表及接收广播函数，固定失败交错；两处修复仅改其一都会失败。测试文件`test_data_parallel_controller.py`从31项中1失败变为全部通过。
- **限制：**初次GPU前后测试使用同集群不同节点；作者另做同节点回退对照，区分取消丢失与tokenizer调用迟缓。不能把“取消返回后收到几个token”一概归因于该竞态。

来源：[模型、配置、CPU入口及GPU对照](https://github.com/sgl-project/sglang/pull/50147)。

## 4. SGLang：确定性开关，还需要“冷请求对缓存命中”验证

**日期／状态：10月17日提出，北京时间11月15日17:36合入；本期报告合入进展。**

- **发现方式：**已有issue诊断发现，SM12x的ModelOpt静态FP8线性层在冷prefill与较短缓存后缀之间改变归约安排，即使开启确定性推理，同输入评分仍不同。
- **修复：**仅在SM12x确定性模式使用固定N／K分块的Triton GEMM，并对不足K分块的加载补零。常规模式和强制Marlin路径不变。
- **验证环境：**RTX 5090、400W、TP1，官方`0.5.23.dev20261020+g55b2aef7ad` nightly，Qwen3-8B-FP8固定模型修订，BF16激活、Triton attention。原作者记录137项测试通过，真实模型18组冷／缓存配对评分零差异。
- **回归入口：**新增缓存后缀比较和CUDA Graph回放，覆盖BF16／FP16、偏置、非连续3D输入及K=80尾部；完整脚本、输出与哈希保存在公开验证目录。
- **限制：**上述验证发生于10月，不是本日新实验；两级／三级流水的128题输出一致属于修复内部保持性检查，不证明相对上游准确率提高。原始混合模型TP2、SM121和`torch.compile`未在该本地实验验证。

来源：[修复及证据边界](https://github.com/sgl-project/sglang/pull/44861) · [原始脚本与结果](https://github.com/yibol9768-alt/sglang/blob/ef2c6cde610839e88a830f7a7cbcbb06c551e3d4/validation/rtx5090-20261017/round4/README.md)。

## 5. SGLang：特殊GQA比例，暴露常规形状没有覆盖的精度错误

**日期／状态：11月1日提出，北京时间11月15日15:06合入。**

- **原始症状：**GLM-4-32B-0414在Triton decode上部分query head读取错误KV head，作者H100、greedy、1,319题GSM8K的逐步推理提示测试从50.87%恢复至93.48%，与FA3对照一致。
- **触发结构：**GQA组大于16且不是16整数倍，例如48个query head／2个KV head，组大小24。旧tile横跨两个组，映射错位；修复为每个KV head分配整数个tile并屏蔽尾部。
- **检出／回归：**增加组大小24、20、8、16、32对照。另有公开独立复核：CMP 170HX、Torch 2.14.0、Triton 3.8，BF16输入对FP32 Torch参考；组24最大绝对误差从2.25135降至0.004783，通过`atol=rtol=1e-2`。
- **限制：**改变提示模板后各组GSM8K均明显降低，不能脱离提示与后端报告准确率。正确kernel在受影响形状更慢，旧性能优势来自错误计算；独立复核是合成kernel测试，不是服务性能验证。

来源：[修复及模型对照](https://github.com/sgl-project/sglang/pull/47802) · [模型复现脚本](https://gist.github.com/EvanZhuang/e205b5d8038c23ab414fccb6abdaa22a) · [独立数值复核](https://github.com/sgl-project/sglang/pull/47802#issuecomment-6873781950)。

## 6. SGLang：高端卡CI通过，不能代表旧架构kernel可编译

**日期／状态：11月14日提出，北京时间11月15日17:37合入。**

- **发现方式：**RTX A4500（SM86）运行FastHunyuan视频请求，去噪一开始便因`griddepcontrol`需要SM90以上而编译失败。同一既有数值测试在A4500失败、H200通过，CI却只注册H100。
- **复现：**启动`FastVideo/FastHunyuan-diffusers`并配置DiT逐层offload，向`/v1/videos`发送848×480、33帧请求；PR给出命令和错误栈。
- **修复／判定：**不再无条件启用PDL，而按硬件能力决定。基线`4a4f400022`上原测试文件1失败、103通过、22跳过；修复后106通过、22跳过。SM86无PDL kernel与RMSNorm参考满足`atol/rtol=2e-2`，视频请求完成。
- **回归与限制：**新增架构模拟测试覆盖开关分支，但模拟不能替代真实编译；A100和Ada未实机验证，性能未测。

来源：[配置、数值测试及架构覆盖缺口](https://github.com/sgl-project/sglang/pull/50530)。

## 优先验证的两个方向

1. **状态与控制路径差分。**同一输入分别运行冷缓存、部分命中、完整命中、取消后重入，比较token／logprob、缓存状态位置与终止原因，而不是只看HTTP成功率。
2. **把结构边界加入测试矩阵。**覆盖非整除GQA组、跨`2^31`的地址乘积、低于主CI硬件代际的kernel编译；以小型不变量测试提高检错效率，再用真实模型和负载复核。

以上两项为建议，不是本次执行结果。本期核查了PR元数据、说明和代码差异；**作者本地测试通过不等于全部上游CI通过**，部分PR页面仍有失败CI记录，未将其解释为修复相关失败或忽略。没有足够新增证据补充AI生成测试、GUI自愈或训练检查点案例，因此不凑栏目、不声称覆盖全部新进展。
