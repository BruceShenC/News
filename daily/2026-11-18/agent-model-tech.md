# Agent 与大模型技术热点｜2026-11-18

**观察窗口：**北京时间 2026-11-17 09:30 至 11-18 09:30；补充一项近七日研究。官网只标日期的条目保留原日期，不推断精确发布时间。本期筛选 5 项，重点是技术路线与落地边界，不把厂商自测或发布密度当作独立热度证据。

## 1. Foundry IQ：把检索规划、知识图谱和权限放进同一层

**动态与状态｜11 月 17 日官方发布。**知识图谱和 Microsoft Retriever 1 均为公开预览；SharePoint 权限感知知识源已正式可用。Serverless 正式可用则计划在 12 月，不是今天已全面上线。

**技术要点：**图谱按本体关联跨文档实体，并保留关系来源；主题层用于全库概括类问题。Retriever 1 专门规划检索，不再要求用前沿通用模型承担每次搜索计划。支持并正确配置的数据源在调用者身份下执行权限检查，MCP 入口也适用。

**为什么值得看：**企业 RAG 的竞争点从“找相似片段”移向“组织关系、规划搜索、保留证据与权限”。对 Knowledge Gateway，值得借鉴的是这些职责的统一接口，而不是直接假设图谱一定胜过向量检索。

**边界：**减少搜索次数和成本是厂商设计目标，尚不能替代同一语料、同一答案质量下的对照实验。来源：[Foundry IQ 官方发布](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/foundry-iq-introducing-knowledge-graphs-engineered-for-agents/4572683)。

## 2. Windows 治理型 Agent：权限边界下沉到操作系统

**动态与状态｜11 月 17 日。**微软介绍 Windows 企业 Agent 部署架构；Intune 中的 MXC 配置处于私有预览，不能理解为所有 Windows Agent 已自动获得完整保护。

**技术要点：**将 Agent 身份与用户身份分离，用 Entra Agent ID 标识执行者；MXC 在系统层限制进程、文件、网络和工具访问，并按风险选择进程隔离或独立会话。企业策略设定上限，本地和会话策略只能进一步收紧。

**为什么值得看：**提示词里的“不要越权”不是安全边界。把身份、资源能力和隔离放到模型外部，才更接近可治理的长时间运行 Agent。

**边界：**需要受支持的 Agent 与管理配置配合。“先观察后强制”有助于制定策略，但官方也提示观测并不完整，仍需显式验证资源访问与异常路径。来源：[Windows 开发者官方说明](https://blogs.windows.com/windowsdeveloper/2026/11/17/enterprise-deployment-of-governed-agents-on-windows/)。

## 3. MAI Code 2 / Flash：按任务成本分层，而不是只追最高分

**动态与状态｜11 月 17 日。**微软发布两款编程模型，官方列出 GitHub Copilot 可用；Code 2 Flash 在 Microsoft Foundry 为有限访问预览，其他托管渠道不能一概视为已开放。

**技术要点：**Code 2 定位深度调试、多文件修改和仓库推理；Flash 面向高频常规编辑。对 Agent 系统的启示是把简单修改与复杂调查分流，而不是让所有步骤都使用同一高价模型。

**为什么值得看：**厂商把实际软件工作与单位成本作为主要卖点，但也明确尚未针对更难的基础科学任务或极长时间跨度任务优化。这比“通用最强”更适合指导路由设计。

**边界：**官方跨模型成本/成绩比较含 50% 推广折扣，部分测试使用特定 Copilot CLI、最大推理强度且不使用子 Agent；不可外推为任意生产负载的固定降本比例。来源：[MAI Code 2 官方发布与测试注释](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)。

## 4. MAI Realtime 1：语音轮次控制与工具推理开始合并设计

**动态与状态｜11 月 17 日。**实时语音模型提供 MAI Labs 体验和 Foundry 有限访问预览，并非全面正式可用。

**技术要点：**将语音到语音交互与自适应推理结合，覆盖打断、短回应、等待、噪声环境和企业工具调用。其价值不只是更快发声，而是让“何时听、何时答、何时调用工具”协同工作。官方宣称兼容 OpenAI Realtime API，可降低接口迁移工作，但不等于行为完全一致。

**为什么值得看：**语音 Agent 的成功率取决于轮次与任务执行共同表现，单看首音延迟会遗漏打断恢复、误触发操作和重复执行。

**边界：**官方基准属于厂商报告；预览可用性和商用条款需分别核对。MAI Labs 体验面向个人非商业使用，不能拿它直接替代企业部署入口。来源：[官方发布](https://microsoft.ai/news/introducing-mai-realtime-1/)、[模型体验说明](https://microsoft.ai/models/mai-realtime-1/)。

## 5. K2-Horizon：同时开放训练脉络与探索共享模型的推测解码

**动态与状态｜近七日补充，论文于 11 月 16 日提交。**这是研究报告，不是今天的新商用 API 发布。系列从 0.9B 稠密模型扩展到 375B、激活 23B 的 MoE，并强调数据、检查点、训练日志及基础设施的可追溯性。

**技术要点：**MoVA 把专家机制放入注意力的 value 投影，并结合 softplus 门控；Uno 用基座模型上的适配器承担草拟，与验证共享模型和 KV 缓存，减少另养一个草稿模型的负担。

**为什么值得看：**一条路线优化激活计算，另一条优化解码系统开销；开放中间产物则有助于解释收益来自哪里，而不只是比较最终权重分数。

**边界：**论文 7B Uno 的 2.2 倍结果来自单 H200、Nano-vLLM、1K 输入/8K 输出、batch=1 等特定设置；batch=64 时约 1.5 倍，不能写成普遍服务吞吐提升。未在本期自行复现。来源：[论文摘要与提交记录](https://arxiv.org/abs/2611.21003)、[方法与实验正文](https://arxiv.org/html/2611.21003v1)。

## 接下来值得跟踪的两个方向

1. **企业知识入口从检索 API 走向上下文治理。**优先比较带权限的多跳问题、跨文档证据与全库概括三类任务，观察答案质量、搜索次数和总成本是否同时改善，而不是只统计召回率。
2. **Agent 的模型路由与系统权限协同。**低成本模型承担常规步骤、强模型负责复杂调查，但二者共享明确的资源权限和操作审计。模型更便宜不应意味着可执行动作更宽松。
