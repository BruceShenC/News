**1．Axion 1.0：简化 Agent 后训练，权重仍待发布**

事件：11月2日22:48提交论文；论文、训练配方及代码可访问，官方仓库当前明确写着模型权重“coming soon”，不能按已可下载模型介绍。

变化：两阶段监督微调分别处理自包含推理、依赖工具的推理，再接强化学习，不使用专门的中期训练、DPO 或在线策略蒸馏。重点是按底座能力强化题目，并用真实数据和确定性计算构造可核验工具任务。

价值与限制：适合研究 Agent 后训练的数据团队，值得看“任务与数据怎么设计”，而非只比较训练阶段数量。官方配方包含35B与122B级模型；流程简单不代表算力需求低，不能把论文的竞争性成绩当作已独立验证的产品能力。仓库代码标注 Apache-2.0，模型与数据的使用条件仍需分别确认。

来源：[论文与提交记录](https://arxiv.org/abs/2611.03233)、[官方代码及权重状态](https://github.com/bytedance/axion1_0)。

**2．Strategist：让推理策略本身成为可积累的程序库**

事件：11月3日02:51提交论文，属于研究结果。

变化：冻结底层模型，把多次模型调用组成的推理过程写成可执行 blueprint。元 Agent 检索已有策略，在小型开发集上生成、执行、修改候选，并将策略及测量结果积累到共享库，而不是每个任务重新手写流程。

作者报告：30个基准中24个超过最强基线；平均准确率74.7%对74.0%，推理成本降低39%。这些是指定基准、模型和成本口径下的结果，不是所有应用的账单降幅。

价值与限制：适合有重复任务和固定开发集的团队研究“复用推理流程”。部署前应另计策略搜索成本，并用独立任务检验迁移；执行自动生成的策略代码也需要隔离。论文收益不能直接推广到长期线上操作任务。

来源：[论文及日期](https://arxiv.org/abs/2611.03618)、[方法、成本口径与跨任务实验](https://arxiv.org/html/2611.03618v1)。

**3．KernelSeek：用问题引导优化方向，而非不断给 Agent 加工具**

事件：11月3日01:51提交研究论文。

变化：保留可核验目标和最小执行框架，在关键决策点用问题迫使 Agent 改查瓶颈所在层级；先由人提问，再形成可自问的问题库。技术重点是搜索方向，不是宣称完全无人参与。

作者报告：生成的 Hopper、Blackwell 注意力前向内核，在各182个场景上通过其正确性检查，几何平均性能分别为 FlashAttention-3 的1.16倍、FlashAttention-4 的1.46倍。研究记录包含162条人类消息，不能称为纯自主成果。

价值与限制：适合 GPU 性能工程团队阅读问题库。论文明确不覆盖反向传播，Blackwell实现尚未支持FP8输入及部分较大头维度；局部内核加速也不等于端到端服务等比例加速。本期只介绍优化方法，不重复缺陷回归细节。

来源：[论文与日期](https://arxiv.org/abs/2611.03517)、[完整方法及局限](https://arxiv.org/html/2611.03517v1)。

**4．ScienceCUA：把软件文档拆成操作技能与按需参考**

事件：11月2日22:50提交研究论文。

变化：从软件文档构建可复用操作 Skills，将命令目录、语法和快捷方式单独存为 References；再比较同一任务的成功与失败轨迹，修订技能，并在多次执行验证后更新技能库。

作者报告：初始资源对平均成功率的提升最高7.23个百分点，加入演化后的总提升最高17.12个百分点。这是不同实验设置中的“最高值”，不能当作每种软件都能获得的收益。

价值与限制：适合科学软件自动化与企业知识工程。值得借鉴的是“程序性操作知识”和“查询资料”分开，以及演化任务与测试任务隔离。效果仍依赖文档与部署版本匹配、任务覆盖和具体软件环境；不是通用即插即用的单一 Skill，也不纳入独立 Skill 星数榜。

来源：[论文与日期](https://arxiv.org/abs/2611.03238)、[方法与具体实验](https://arxiv.org/html/2611.03238v1)。

**5．CoworkOS：把长任务的策略与执行状态管理分开**

事件：11月2日22:15提交研究论文。

变化：模型负责动作、委派和验收，运行时负责状态、反馈及持续任务；层级工作区、持久语义记忆和作业记录支持跨 Agent、跨会话接续。人和 Agent 还能直接修改同一份文档或设计产物，而不仅通过聊天协作。

价值：对长周期研究、设计交付和多 Agent 产品，值得关注状态恢复与共享产物是否成为架构的一等对象。

限制：论文跨基准成绩和自动后训练案例属于作者实验，不能证明任意业务都能稳定长期运行。建议评估时单独检查中断恢复、并发修改及委派权限；这是本简报建议，不是已经执行的验证。持久记忆和后台作业增加的数据保留、权限与成本责任也不能靠模型能力替代。

来源：[论文与日期](https://arxiv.org/abs/2611.03178)、[运行时、工作区和记忆架构](https://arxiv.org/html/2611.03178v1)。

**6．Frozen Tape Modules：把有界工具计算放进模型前向过程**

事件：10月31日17:54提交研究论文，作为近7日模型架构补充。

变化：可训练 writer 把隐藏状态变成离散符号带，独立训练后冻结的小模块执行计算，再由 reader 把结果送回模型，减少文本工具调用的解码开销。

作者在 gemma-3-1b-it 的算术与物体追踪任务上验证；带标注符号带训练的版本答对全部750个追踪题，七人设置的GPU内核耗时约为文本工具基线的十分之一。

价值与限制：值得小模型、专用推理模块研究者阅读。但它处理的是返回单一符号的有界计算，不是浏览器、搜索或任意 API 的替代品。仅凭答案训练的版本并不稳定，输入抽取和是否触发模块仍是主要难题；内核耗时不等于端到端用户延迟。

来源：[论文、提交日期及作者实验范围](https://arxiv.org/abs/2611.00783)。

**值得继续关注的两个方向**

- 从手写固定流程转向可测量、可积累的策略与技能。优先深入阅读 Strategist 与 ScienceCUA：前者复用推理程序，后者把文档知识变成可修订操作知识。共同难点是避免开发集过拟合、保留适用版本、控制代码与工具权限。
- 不仅扩大模型，还重新分配模型、工具和运行时的职责。Axion关注训练数据与阶段，KernelSeek关注搜索引导，CoworkOS关注持久状态，Frozen Tape Modules则把部分计算移入前向过程。它们解决不同层级的问题，不宜合并成一个泛化的“自主性突破”。

本期建议先读 Strategist 的策略与成本测量设计，以及 KernelSeek 的问题库。若进一步验证，只在隔离环境、有限任务和明确预算内进行；本次未安装、运行或复现任何项目。未确认的重要发布不作断言，预印本与作者实验也不等于成熟、安全的生产方案。
