# Agent 与大模型技术热点｜2026-11-17

**观察窗口：北京时间11月16日09:30至11月17日09:30，结合近7日背景。** 本期两项当日模型发布、三项近周技术进展。核心变化是：模型更强调单位任务成本，Agent基础设施开始明确身份、权限和实时执行边界。厂商性能与论文实验均为原作者报告，本期未调用模型或独立复现。

## 1. Qwen4-Max正式发布：稀疏架构与原生视觉面向长程工作

**日期／状态：11月16日正式发布，API已提供；小型开放权重版本仍是预告。**

官方称总参数2.4T，每token激活71B，并升级注意力、残差连接和嵌入设计；支持原生视觉及百万token上下文。模型文档列出图像／视频输入、文本输出、并行工具调用和结构化输出。

**价值：** 将多模态理解与工具执行放在同一模型接口中，适合需要跨文档、截图和代码处理的工作流。官方Work360结果显示High模式比前代少用35% token，但属于自有基准，不是任意任务保证。

**接入限制：** 不能把API协议兼容理解为参数语义完全相同。文档将部分协议中的medium映射为high，且默认开启思考；迁移时需显式核对预算与推理档位。百万上下文也不等于任意位置的信息都能可靠利用。

来源：[正式公告](https://www.alibabacloud.com/en/press-room/alibaba-unveils-qwen4-max?_p_lc=1) · [能力、上下文与参数文档](https://www.alibabacloud.com/help/en/model-studio/qwen4-max)

## 2. Hy4 flash：用较小激活规模、缓存压缩和短输出降低任务成本

**日期／状态：11月16日正式发布并接入TokenHub等产品；开源权重是后续计划，不能写成已开源。**

腾讯披露224B总参数、12B激活参数，采用混合注意力、LatentMoE及Engram；官方称KV cache为Hy4的六分之一。后训练结合自蒸馏与强化学习，目标包括减少完成任务所需输出。

**价值：** 关注点从每百万token价格进一步转向完成一项工作的总token、耗时和产物质量。官方列出的每百万token输入／输出／缓存命中价为人民币0.5／2／0.02元，另有至11月30日前的限时促销；实际计费需以适用平台条款为准，勿重复叠加折扣。

**限制：** WorkIndex成本优势与150+ token/s解码速度均为厂商报告，不是同配置独立对比或你的端到端延迟。较少激活参数也不代表全部权重占用小。

来源：[腾讯正式公告及测量口径](https://www.tencent.com/zh-cn/tencent-launches-hy4-flash-to-power-high-speed-cost-efficient-ai-deployment-for-everyday-workflows/)

## 3. Poppy 1.0：个人Agent连接企业时，先发现能力再处理授权

**日期／状态：11月13日发布协议1.0，属于近7日进展，不是今天首次发布。**

Personal Agent Protocol在MCP、OpenAPI、UCP等既有标准之上，组织企业入口、会话、身份与授权。Sierra称Shopify商店已自动发布Poppy文件；这是部署声明，不能直接当作所有商家业务都已自动化。

**价值：** UCP处理购物流程，Poppy侧重Agent到达企业时如何发现接口、表明身份并建立访问。行业扩展可以与核心协议分离，降低逐站适配成本。

**关键边界：** 规范明确企业返回的网页、工具描述和Skill只是数据，不提供用户同意，也不能扩大OAuth权限；凭证不应进入模型上下文。协议可减少接口歧义，但不能自动消除提示注入或证明所有实现安全。

来源：[1.0发布公告](https://sierra.ai/blog/releasing-poppy) · [正式规范，尤其第9.4及10节](https://personalagentprotocol.org/docs/1.0/spec)

## 4. Gamer：实时视觉行动不必每一步都生成长推理

**日期／状态：11月13日16:39 UTC提交，即北京时间11月14日；研究预印本。**

Gamer将视觉观察、键鼠动作、稀疏推理和跨上下文记忆放在同一策略中。常规控制直接输出动作；关键决策或记忆更新时才生成显式推理。旧上下文移出前形成摘要，保留任务进度与近期细节。

**价值：** 把“何时思考”和“何时行动”共同训练，比给实时任务套用每步长思维链更贴近延迟约束。其Streaming-vLLM也同时优化视觉、上下文与动作解码。

**限制：** 论文在特定H200 MoE配置报告端到端延迟约1.31秒降至65毫秒，不能当作任意设备结果；由吞吐推算的控制率不是实测游戏帧率。作者承认环境覆盖有限，持续快速操作不等于解决复杂战略问题。

来源：[提交记录](https://arxiv.org/abs/2611.18397) · [方法、性能口径及局限](https://arxiv.org/html/2611.18397v1)

## 5. A³：端云协作的关键是“什么时候不再等云端”

**日期／状态：11月13日提交；近7日研究预印本。**

A³按完整ASR／语言模型／TTS阶段安排端云执行，依据链路状态和历史延迟决定何时启动本地备用路径，先完成者返回，并限制备用并发。它还按带宽决定云端返回语音还是文本。

**价值：** 展示一种不同于简单大小模型路由的协作方式：保留可独立完成任务的本地链路，再决定等待与重复计算的取舍。作者的设备实验中，跨网络拆分投机解码因逐步往返反而更慢。

**限制：** 完整本地兜底依赖内存容量；论文中的8GB Orin Nano无法容纳完整管线，不能在全断网时保证回答。实机每格仅24次请求，小差异只能视为趋势；云端路径仍上传音频，不是默认本地隐私方案。

来源：[提交记录](https://arxiv.org/abs/2611.18064) · [系统设计、实验和资源边界](https://arxiv.org/html/2611.18064v1)

## 值得继续关注的两个方向

1. **从token单价转向单位成功任务成本。** Qwen4-Max与Hy4 flash都强调减少任务消耗。可用固定真实工作流比较成功率、总输入／输出及缓存token、重试次数与总耗时，再判断成本变化；以上为建议，不是本次执行结果。
2. **把模型能力与运行时边界一起设计。** Poppy明确身份和授权，Gamer区分快速行动与关键推理，A³处理端云等待。我的判断是，长期Agent的可用性越来越取决于这些运行机制，而不只是换更大的模型。
