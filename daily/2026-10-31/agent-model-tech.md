**1．Gemini Computer Use 正式 GA：视觉行动接口覆盖三类环境**
事件日期：10月30日。**正式发布，非新基础模型。**
Google 将 Computer Use 工具在 Interactions 和 GenerateContent 两套 API 中转为 GA。模型通过截图理解界面、返回点击/输入等动作，客户端执行并回传新截图；文档覆盖浏览器、移动端和桌面，Gemini 4/3.x 还提供动作 intent、可配置安全策略及可选截图提示注入检测。
价值：可统一不同 GUI 的“观察→决策→执行”接口，适用于跨系统操作及无完整 API 的工作流。
限制：它不是托管执行环境，开发者仍需实现执行器、坐标映射、沙箱和确认交互。GA 不代表网页内容可信或动作永远正确；提示注入检测为显式开启能力，不能替代权限隔离。这里未把全部文档能力都归为10月30日新增。
[官方更新日志](https://ai.google.dev/gemini-api/docs/changelog#october-30-2026) · [机制与安全边界](https://ai.google.dev/gemini-api/docs/computer-use)

**2．CORAL：让 Agent 自己决定何时保存进度、清空上下文**
论文日期：10月29日提交，30日公告。**研究结果；arXiv元数据注明获 COLM 2026 接收。**
提供两个可调用工具：把计划进度与事实写入工作记忆，再主动结束当前推理片段，仅保留任务、系统指令和检查点重新开始。训练先用 SFT 学检查点，再用跨片段 ARPO 优化，不只是达到长度阈值后的被动摘要。
作者报告：8B模型在GAIA达到42.8%平均准确率，相比ReAct消耗约6–7倍更少的输入token；这不是端到端费用或时延同幅下降的证明。适合长链路检索、反复尝试的Agent任务。
关键限制：清空原始证据后，错误记忆更难纠正。论文的干预实验显示，重置后被污染的事实不会被纠正；检查点应保留证据出处与不确定性，而非把摘要当无条件事实。训练中的跨片段奖励仍等量分配，信用分配尚粗糙。
[论文与限制](https://arxiv.org/html/2610.40350v1) · [论文元数据](https://arxiv.org/abs/2610.40350)

**3．双通道长期记忆：事件叙述与关系元组各保留一份**
论文日期：10月29日提交，30日公告。**Microsoft作者的预印本研究。**
一条记忆路径保存带时间的事件摘要与细节；另一条提取“实体、关系、对象、时间、来源上下文”。查询时分别检索两库，离线再用聚类和模型合并冗余、清理过时条目。不同于只扩大上下文，也不同于只存知识图谱。
作者报告：gpt-4.1-mini在LongMemEval-S得到85.5%，检索上下文约3–6.9K tokens；LoCoMo模型裁判分数为90.2%。适合跨会话事实、时间和人物关系共存的助手。
限制：90.2%不是所有指标领先，同表全上下文为91.3%；部分基线沿用前人结果。合并压缩约16.34%的记忆条目，但并非完全无损，LoCoMo总体分数略降。只覆盖两项对话记忆基准，不能直接外推生产场景中的删除纠错和访问控制。
[论文、数据表与消融](https://arxiv.org/html/2610.39790v1)

**4．SPLICE：多Agent不是越多通信越好，而是找缺失的那条边**
论文日期：10月29日提交，30日公告。**预印本研究。**
固定工作流跑完后，定位“证据被某Agent找到，却没传给需要它的Agent”的信息缺口，只补一条有向连接，重跑接收者及受影响下游。再根据中间输出变化、证据来源及影响是否传播到最终答案，选择保留原答案还是采用新答案。
在作者半预算设置中，ToolBench Micro为0.6856，较静态流程增加0.0509；四项推理/规划基准的加权平均增加0.0377，费用分别约为原流程1.44倍和1.25倍。价值在于把通信拓扑修复变成可选择的操作，减少错误意见扩散。
限制：主实验节点用gpt-4o-mini，选择器为DPO训练的Qwen2.5-7B；ToolBench使用归档API响应。**回退只发生在输出层，不会撤销已执行的工具动作**，因此不能把它当真实外部操作的事务回滚。
[论文与实验设置](https://arxiv.org/html/2610.40186v1)

**5．Multi-View MoE：路由器不只选专家，也决定专家看到什么**
论文日期：10月29日提交，30日公告；稿件封面日期为28日。**Baidu ERNIE团队预印本研究，非新模型产品发布。**
多个独立初始化的路由头汇总分数选专家，再把各路由头对该专家的相对偏好用于混合潜在视图，给每个选中专家形成不同输入。每个专家仍只执行一次，在固定激活专家数下提升选择和计算的匹配度。
作者在24层、总参数10B/激活约1B、训练708B tokens的设置中，九项任务均分提升1.18个百分点；只用多路由头提升0.6个百分点。适合研究MoE容量利用，而非单纯增加专家。
限制：保持的是专家FLOPs与all-to-all通信量，**不等于零额外总开销**；路由、投影、混合仍有计算，参数约增加0.19%。主要证据来自一个规模与共享训练种子，不能据此推断超大模型或任意部署吞吐收益。
[论文与成本分析](https://arxiv.org/html/2610.40577v1)

**6．PIVOT：学生全部做错时，让教师在中途纠偏并提供密集监督**
论文日期：10月29日提交，30日公告。**预印本研究；文中称完整训练代码和检查点将在评审结束后公开。**
针对RLVR一组采样全错、没有有效奖励的问题，在学生已生成的轨迹中插入教师纠正，再让学生继续；同时对教师片段施加token级KL监督，与可验证结果奖励联合训练。关键是“走到可成功路径”与“学会教师做法”同时发生。
作者在三类困难逻辑游戏中报告，平均avg@8从最佳基线19.5%提升至35.6%；这是多次采样平均准确率，不是pass@8，也不是所有领域的能力翻倍。适合有可执行判分器、基础模型成功轨迹稀少的训练任务。
限制：验证集中在逻辑与数学；教师纠正长度、介入位置与剩余回答预算影响很大，目前配置固定，尚未证明对代码、开放式任务或动态教学调度同样有效。
[论文、方法及开放计划](https://arxiv.org/html/2610.40576v1)

**值得关注的两个方向**

• **把信息管理纳入Agent策略，但保留证据链。** CORAL选择何时忘掉上下文，双记忆选择存什么，SPLICE选择把证据传给谁。能力提升可能来自信息组织，而不只是更大模型；原始证据、时间和来源丢失则会形成新的脆弱点。

• **在固定主要预算内改变计算方式。** Multi-View重新分配专家输入，PIVOT把教师信号集中在可学习的纠错片段。比较时应同时核算新增训练/检索/选择器成本，不能只看主干FLOPs或最终分数。

本期仅研究公开资料，未调用模型、运行实验或安装项目；上述结果不代表生产成熟度或安全保证。
