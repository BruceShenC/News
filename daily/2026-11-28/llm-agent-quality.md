# 大模型与 Agent 质量、测试与工程资讯｜2026-11-28

**今天最值得带进质量门禁的两件事：用非零权重检查模型是否真的加载正确，用已知时序检查压测工具的吞吐分母是否正确。** 优先观察北京时间 11 月 27 日 09:00 至 28 日 09:00，补充近 7 日相关证据。下文区分作者实测、评审复现和未执行的建议。

## 推理与训练工程质量

1. **vLLM：量化模型能启动、分数不变，仍可能漏加载 MoE 路由权重。** 11 月 27 日，开放 PR #70261 的作者在 vLLM main `29fa74e`、单张 B200 上对照：BF16 Laguna-XS.2 在启动时报未加载路由校正偏置；NVFP4 能启动，但保留默认零值，恰好与公开权重的全零偏置相同，GSM8K 修复前后均为 0.9060。作者构造含 8 个非零偏置的小 checkpoint：FP8 在修复前仍全零，修复后与 checkpoint 一致；新增 `tests/models/language/generation/test_laguna.py::test_routes_with_checkpoint_e_score_correction_bias` 亦由失败转通过。**建议门禁：** 同时保留全零控制组和非零探针，对照 checkpoint 与各层加载结果，再用固定输入验证专家选择一致；冷加载和权重热更新分开测。未独立实测，多卡未由这组证据覆盖。[作者复现、脚本与测试入口](https://github.com/vllm-project/vllm/pull/70261)

2. **SGLang：Rust 压测客户端多等一次，导致吞吐被低估。** 11 月 26 日问题报告：main 上以 0.2 请求/秒、seed 42 发一个 mock 请求，实际请求约 2.5 ms、报告整轮 6.75 s。源码证实计时包住派发流程，旧逻辑最后一次提交后也可能等待；总请求与 token 吞吐均用整轮时间作分母。开放 PR #53427（`43dba19`）只跳过最后一次到达间隔，仍等待已派发请求完成。作者报告 43 个单测通过；新增虚拟时钟用例覆盖首尾和真实间隔，但请求都提前失败，没验证成功响应的吞吐。**建议验收：** 三个合成成功响应共 60 个输出 token，在第 0/2/6 秒提交，第 1/3/15 秒完成。只改变末次提交后的抽样间隔（7→11 秒），都应得到 15 秒和 4 tok/s；旧逻辑遇短间隔可能被真实慢响应掩盖，长间隔会报 17 秒。固定时长的稳态压测另定义 token 计入规则，并单列结束后的排空时间。没有证据表明模型本身变慢。[问题报告](https://github.com/sgl-project/sglang/issues/53426) · [补丁与测试](https://github.com/sgl-project/sglang/pull/53427)

3. **DeepSpeed：恢复失败要看所有 rank 是否都退出。** 11 月 27 日，作者从 ZeRO-3 的 1 卡 checkpoint 恢复到 2 卡时发现缺分片只报裸断言。开放 PR #9180 增加带路径的错误；作者在 2×RTX A4000、PyTorch 2.6.0 上报告检查点用例从 141 通过/3 失败变为 144 通过。随后评审指出 Reflow 中一个 rank 提前报错会让另一个卡在集合通信；作者称把检查移到 prologue 之后（`9622af1`），同场景从挂起变为两个 rank 都报错。这是错误报告改善，不是实现了跨规模恢复；缺文件与拓扑不兼容仍应分别判定，诊断中的保存规模推断也有评审疑问。**建议验收：** 分开测错误 tag、单 rank 缺文件、原拓扑正常恢复；错误组要在设定超时内收齐所有 rank 的结果，正常组还要验证下一批数据和第一步更新。[PR、测试入口与复验记录](https://github.com/deepspeedai/DeepSpeed/pull/9180)

4. **vLLM Responses 流式工具调用：连接不断，还要验参数和调用身份。** 11 月 26 日报告在 `0.34.0rc1.dev619+g352dbd1db` 的约 1,600 次请求中一次中途结束，服务仍健康，客户端没收到完成或错误事件；这是单次观察，不是线上故障率。11 月 27 日，评审对较早的开放补丁 #55371 报告：把正文与同一调用的参数尾部分帧后，一次调用可能被拆成两个、产生新 ID，且各自发出结束事件。另一个开放补丁 #70260 作者报告 18 个测试通过，但评审在较早提交发现跨索引错用身份，后续提交的评审也指出迟到名称的命名空间处理问题。**建议验收：** 用无副作用的 mock 工具重放同一逻辑调用的不同合法分帧，断言参数完整、ID 不变、只完成一次、只执行一次；另用两个真实逻辑调用作对照，防止把两个合成一个。未在真实模型重跑。[原始问题](https://github.com/vllm-project/vllm/issues/70053) · [分帧评审](https://github.com/vllm-project/vllm/pull/55371) · [新补丁及评审](https://github.com/vllm-project/vllm/pull/70260)

## AI 辅助测试

5. **SpecEngineeringBench：高通过和高覆盖不等于测试能抓到缺陷。** 11 月 25 日预印本用 100 个 Python 案例，给 Agent 需求和待验证代码，再将同一组生成测试分别跑在缺陷版与修复版上。作者报告七个 Agent 平均修复版通过率 91.47%、变更聚焦覆盖 80.48%、缺陷版失败且修复版通过的比例 26.36%。三项口径和聚合不同，不能相减，也不能把 26.36% 当成所有缺陷的检出率。**适用做法：** 对跨 PR 的大需求冻结同一条业务断言。例如固定「保存新值后导出必须读到新值」，用仍返回旧值的合成缺陷版证明能红，用正确版证明能绿；不让生成器看到缺陷位置。该做法未实测。[论文及指标定义](https://arxiv.org/pdf/2611.32973) · [项目页](https://github.com/TokenWave-AI/SpecEngineeringBench)

**优先验证：** 我会先做压测计时的 mock 对照，成本低且能避免把客户端误差带进容量结论。随后再把「全零＋非零」权重夹具加入模型接入门禁，覆盖普通加载与量化加载。
